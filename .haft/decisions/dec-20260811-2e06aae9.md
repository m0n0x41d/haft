# Store every EvidenceRecord in its own versioned Markdown carrier for Haft 9.1.0 without breaking public CLI or MCP contracts

## 1. Problem Frame

**Problem statement:** Evidence attached in Haft is stored in the local SQLite evidence_items table without a version-controlled carrier, so git collaboration and clean database reconstruction lose EvidenceRecords and may silently lose evidence fields.

## 2. Decision

**Selected:** Store every EvidenceRecord in its own versioned Markdown carrier for Haft 9.1.0 without breaking public CLI or MCP contracts

**Selection policy:** First satisfy lossless SQLite-Markdown-SQLite round-trip, stable identity, authority preservation, and backward-compatible public interfaces; then prefer merge locality, implementation simplicity, and a clean path to a future EvidenceService.

**Why selected:** A per-record carrier provides lossless, independently mergeable git collaboration, reuses Haft's Markdown structured_data envelope, and keeps the EvidenceRecord distinct from its carrier and parent artifact.


**Invariants:**
- EvidenceRecord, Markdown carrier, supporting basis, Evidence relation, and parent artifact remain distinct.
- Evidence identity, parent binding, content, verdict, source carrier, claim bindings, validity, formality, causal support basis, provenance, and creation time round-trip without silent loss.
- Sync never creates an absent WorkCommission or MethodRun and fails closed for any missing parent.
- Existing public CLI and MCP request and response contracts remain backward-compatible.
- Carrier projection failure leaves the committed semantic row unchanged, creates visible durable projection debt, and is never reported as complete lossless persistence.

**Spec sections:**
- SS.constraints.evidence.001
- SS.functional.evidence-recording.001
- SS.procedural.evidence-refresh.001
- TS.boundary.001

## 3. Rationale

**Counterargument:** One file per record increases file count and requires every evidence mutation, including measurement supersession, to keep its carrier projection current.

**Selected variant weakest link:** Evidence may attach to WorkCommission or MethodRun parents that haft sync intentionally does not reconstruct; their carriers must fail closed when the exact parent is absent and must never create authority.

**Rejected alternatives:**
| Variant | Verdict | Reason |
|---------|---------|--------|
| Store every EvidenceRecord in its own versioned Markdown carrier for Haft 9.1.0 without breaking public CLI or MCP contracts | **Selected** | A per-record carrier provides lossless, independently mer... |
| Embed evidence arrays in parent artifact Markdown | Rejected | Creates hot merge spots and couples unrelated parent schemas. |
| One append-only evidence ledger | Rejected | Produces a shared merge hotspot and makes per-record review harder. |
| Track SQLite in git | Rejected | Binary merge behavior and local runtime state make collaboration unsafe. |
| Defer durable evidence carriers | Rejected | Leaves issue #100 data loss unresolved. |

**Predictions:**
| Claim | Observable | Threshold |
|-------|------------|-----------|
| Evidence survives a clean local database rebuild from git-tracked Markdown carriers. | A round-trip fixture compares every evidence field and parent binding before and after database deletion and haft sync. | Exact equality for all supported fields and identical R_eff, F_eff, G_eff, decay, and freshness. |
| Independent evidence additions do not create parent-carrier merge conflicts. | Two branches attach distinct evidence records to the same parent. | Each branch changes a distinct evidence Markdown file and does not change the parent carrier solely for attachment. |

## 4. Consequences

**Rollback plan:**
Triggers:
- A clean rebuild changes any stored evidence field or computed evidence posture
- Carrier import creates or broadens an authority-bearing parent record
- The additive schema migration cannot preserve a verified rollback snapshot
Steps:
1. Stop emitting and importing the v1 evidence carrier envelope
2. Revert the additive importer and projection code while retaining existing SQLite evidence rows
3. Restore the verified schema-58 pre-migration snapshot when downgrading to 9.0.3
4. Reopen the carrier design against the failed invariant
Blast radius: Evidence carrier projection, evidence sync, and additive ledger schema 59 only; existing parent carriers and public CLI/MCP request and response shapes remain unchanged.

**Affected files:** db/migrations.go, internal/artifact/decision.go, internal/artifact/store.go, internal/artifact/types.go, internal/artifact/verification.go, internal/artifact/writer.go, internal/cli/maintenance_exec.go, internal/cli/serve.go, internal/cli/sync.go
